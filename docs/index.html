API Orders & Hosted Checkout

Integrate seamless payment orders, automated checkout redirection, real-time transaction verification, and instant refunds using the PipraPay REST API.

1. Base URL & Authentication

All API requests must be transmitted securely over HTTPS and include your secret API key in the request header.

BASE https://yourdomain.com/api

* Replace https://yourdomain.com with your installed PipraPay domain or host URL.

API Key Security Notice
Always keep your API key secure. Replace YOUR_API_KEY with your brand's secret token generated from your PipraPay admin dashboard (Brand Settings > API Settings). Never expose it in public or client-side repositories.
Required Request Headers 
MHS-PIPRAPAY-API-KEY: YOUR_API_KEY
Content-Type: application/json

2. Create Payment Order (Gateway Checkout)

Creates a payment transaction order and returns a unique payment identifier (pp_id) and hosted checkout redirect URL (pp_url).

POST https://yourdomain.com/api/checkout/redirect
Required Permission Scope
The API key must have the Create Payment (create_payment) permission scope enabled.
Request Parameters
Field Requirement Description
full_namestring Required Full name of the customer paying for the order.
email_addressstring Required Valid customer email address for transaction receipts and notifications.
mobile_numberstring Required Customer contact phone number.
amountnumber Required The payable amount (must be a positive number).
currencystring Required Active brand currency code (e.g. BDT, USD, INR).
return_urlstring Optional Callback URL where customer is redirected after payment. (Domain must be whitelisted in Brand Domains).
webhook_urlstring Optional Server endpoint for instant payment notifications (IPN). (Domain must be whitelisted in Brand Domains).
metadataobject Optional Custom key-value parameters (e.g. order_id, customer_id) preserved throughout the transaction lifecycle.
Example Request Body 
{
  "full_name": "John Doe",
  "email_address": "johndoe@example.com",
  "mobile_number": "01700000000",
  "amount": 500,
  "currency": "BDT",
  "return_url": "https://yourdomain.com/payment/callback",
  "webhook_url": "https://yourdomain.com/payment/webhook",
  "metadata": {
    "order_id": "ORD-8921",
    "customer_id": "CUST-104"
  }
}
Example Success Response (HTTP 200 OK) 
{
  "pp_id": "9A8B7C6D5E4F3G2H1I0J1K2L3M4",
  "pp_url": "https://yourdomain.com/payment/9A8B7C6D5E4F3G2H1I0J1K2L3M4"
}

5. Webhooks & Instant Payment Notifications (IPN)

When a payment status changes, PipraPay delivers an asynchronous HTTP POST request to your designated webhook_url.

Webhook Security Recommendation
Always verify the transaction by calling the /api/verify-payment endpoint on your backend before releasing digital goods or fulfilling orders. Respond to webhooks with HTTP 200 OK.

6. Mobile Companion & Device Communication Protocol

Complete architectural specification for the PipraPay Android Companion App — device pairing handshake, QR payload parsing, session authentication, sender whitelist synchronization, automated SMS ingestion, and error handling.

POST https://yourdomain.com/
1. HTTP Form Data Transport ($_POST)
All requests must use Content-Type: application/x-www-form-urlencoded or multipart/form-data. The server routes all actions via the action-companion key.
2. Nested JSON Serialization (sms_list)
Top-level parameters are sent as form fields, while complex array structures (e.g. sms_list) are serialized as a JSON string within the POST parameter.
1
Admin Generates Pairing QR Code in Web Panel
In Admin Panel > Devices > Connect Device, a single-use pairing code (OTP) is generated. The QR code embeds:
{BASE_URL}----{ONE_TIME_PASSWORD}
Example: https://payments.example.com----W1X2Y3Z4A5B6C7D8E9F0
2
App Scans QR & Performs login Handshake
The app splits the scanned string by ---- to extract the Base URL and OTP. It then posts device hardware info to the login endpoint. The server consumes the OTP and returns a permanent session token.
3
Continuous Sync & SMS Ingestion
The app stores the session token locally in encrypted storage. All subsequent requests include this token for authentication.
ACTION 1

Device Registration & Authentication (login)

Exchanges a one-time pairing password (OTP) from the QR code for a permanent device session token.

POST Parameters
Parameter Requirement Description
action-companionstring Required Must be set to literal login.
onetimepasswordstring Required The OTP code parsed from the QR code (right-hand side of ----).
namestring Optional Device display nickname (e.g. Samsung Galaxy S22).
modelstring Optional Hardware model number (e.g. SM-S901B).
android_levelstring Optional Android API Level (e.g. 34 for Android 14).
app_versionstring Optional Companion app build version (e.g. 1.2.0).
Example POST Form Payload 
action-companion=login
onetimepassword=W1X2Y3Z4A5B6C7D8E9F0
name=Samsung Galaxy S22
model=SM-S901B
android_level=34
app_version=1.2.0
Success Response (HTTP 200 OK) 
{
  "status": "true",
  "token": "9A8B7C6D5E4F3G2H1I0J1K2L3M4"
}
Error Responses 
// Invalid / expired pairing code
{
  "status": "false",
  "title": "Invalid Credentials",
  "message": "Please enter the correct credentials or scan the QR code again."
}

// Missing onetimepassword
{
  "status": "false",
  "title": "Incomplete Information",
  "message": "Please fill in all required fields before proceeding."
}
ACTION 2

Transmit Captured SMS (sms-transmit-bulk)

Transmits incoming SMS messages captured by the companion app to the server. The server automatically parses MFS provider formats, validates balances, checks SIM slot matching, and reconciles pending checkout orders.

Top-level POST Parameters
Parameter Requirement Description
action-companionstring Required Must be set to literal sms-transmit-bulk.
tokenstring Required Active session token obtained from login.
sms_listJSON string Required Serialized JSON array containing SMS message objects.
Items Inside sms_list Array
Property Requirement Description
idstring Required Local SMS message ID on the Android device (e.g. "1054").
senderstring Required Sender header or phone number (e.g. "bKash", "NAGAD", "16216").
messagestring Required Full, raw message body received from carrier.
simSlotstring | int Required Active SIM card slot index: "1" (Sim1) or "2" (Sim2).
timestampstring Required Unix timestamp in milliseconds or seconds (e.g. "1727712000000").

Prune / Delete Stored SMS Logs (delete-sms-data)

Clears historical SMS records for this device on the server based on category flags.

Mobile Client Code Implementation

Sample production implementation in Android (Kotlin with OkHttp) and Flutter (Dart).

Android (Kotlin & OkHttp) Full Sync Handler 
import okhttp3.*
import org.json.JSONArray
import org.json.JSONObject

class PipraPaySyncService(
    private val baseUrl: String,
    private val client: OkHttpClient = OkHttpClient()
) {

    // 1. Login with OTP scanned from QR code ({baseUrl}----{otp})
    fun authenticateDevice(otp: String, onResult: (String?) -> Unit) {
        val formBody = FormBody.Builder()
            .add("action-companion", "login")
            .add("onetimepassword", otp)
            .add("name", android.os.Build.MODEL)
            .add("model", android.os.Build.DEVICE)
            .add("android_level", android.os.Build.VERSION.SDK_INT.toString())
            .add("app_version", "1.0.0")
            .build()

        val request = Request.Builder()
            .url(baseUrl)
            .post(formBody)
            .build()

        client.newCall(request).enqueue(object : Callback {
            override fun onResponse(call: Call, response: Response) {
                val json = JSONObject(response.body?.string() ?: "{}")
                if (json.optString("status") == "true") {
                    onResult(json.optString("token")) // Save token in EncryptedSharedPreferences
                } else {
                    onResult(null)
                }
            }
            override fun onFailure(call: Call, e: java.io.IOException) = onResult(null)
        })
    }

    // 2. Push Intercepted SMS to Server
    fun transmitSmsBulk(token: String, smsListJsonArray: JSONArray, onComplete: (Boolean) -> Unit) {
        val formBody = FormBody.Builder()
            .add("action-companion", "sms-transmit-bulk")
            .add("token", token)
            .add("sms_list", smsListJsonArray.toString()) // Nested JSON String
            .build()

        val request = Request.Builder()
            .url(baseUrl)
            .post(formBody)
            .build()

        client.newCall(request).enqueue(object : Callback {
            override fun onResponse(call: Call, response: Response) {
                val json = JSONObject(response.body?.string() ?: "{}")
                onComplete(json.optString("status") == "true")
            }
            override fun onFailure(call: Call, e: java.io.IOException) = onComplete(false)
        })
    }
}

async function createPaymentOrder() {
  const apiKey = 'YOUR_API_KEY';
  const endpoint = 'https://yourdomain.com/api/checkout/redirect';

  const payload = {
    full_name: 'John Doe',

  try {
    const response = await axios.post(endpoint, payload, {

        'MHS-PIPRAPAY-API-KEY': apiKey,
        'Content-Type': 'application/json'

    });

    console.log('Payment ID:', response.data.pp_id);
    console.log('Redirect URL:', response.data.pp_url);
    // Redirect client: res.redirect(response.data.pp_url);
  } catch (err) {
    console.error('Payment Error:', err.response?.data || err.message);
  }
}

8. Error Codes & Handling

When an error occurs, the API returns HTTP 400 Bad Request with a structured JSON error object.

API Error Dictionary
Error Code Reason & Troubleshooting
INVALID_API_KEY API key is missing, invalid, or expired. Verify key in Brand Settings > API Settings.
INSUFFICIENT_SCOPE The API key lacks the required permission scope (e.g. Create Payment, Verify Payment, or Refund Payment).
MISSING_FIELD A mandatory parameter (such as full_name, email_address, or mobile_number) is missing.
INVALID_AMOUNT Amount is non-numeric, zero, or negative.
INVALID_CURRENCY Specified currency is not configured or activated for your brand.
INVALID_URL The domain in return_url or webhook_url is not added or is inactive in your whitelisted Brand Domains.
INVALID_PP_ID The transaction reference pp_id could not be found.
INVALID_STATUS Action disallowed for the current payment status (e.g., refund attempted on a non-completed payment).
